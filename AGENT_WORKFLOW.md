# Portable agent workflow contract

> **Purpose:** Make repository continuation independent of any agent, chat session, workstation, or hidden environment.

Any agent working on DAAD Harvester MUST begin from the committed repository state, read `TODO.md` and `preservation_corpus/active_backlog_index.json`, and use the repository-owned scheduler rather than inventing a private shell sequence. The scheduler and this contract are versioned project inputs. A local change is not shared project state until it has passed its focused checks, been committed atomically, and been pushed to the configured remote.

## Required continuation sequence

```bash
# 1. Confirm the checkout and remote without exposing credentials.
git status --short --branch
git remote -v

# 2. Refresh the machine-readable unchecked-task index.
python scripts/build_active_backlog_index.py
python scripts/build_active_backlog_index.py --check

# 3. Run independent read-only gates concurrently.
python scripts/run_parallel_workflow.py --groups evidence publication analysis --workers 4 --timeout 300

# 4. Read TODO.md and select one bounded concern. Never delete or rewrite
#    unrelated unchecked items.

# 5. Run focused tests, then the complete suite.
python -m pytest -q tests/<focused_test>.py
python -m pytest -q

# 6. Deliver only the reviewed concern through the portable wrapper.
python scripts/agent_workflow.py commit --message "type(scope): evidence-backed change"
```

The `agent_workflow.py commit` command refuses to commit when unstaged or untracked files exist, requires a non-empty message, displays the staged file list and statistics, and pushes the reviewed commit to `origin` unless `--no-push` is explicitly selected. This prevents a future agent from silently leaving validated work only in a private checkout. The wrapper never reads, prints, or creates credentials; authentication remains the responsibility of the configured Git client.

## Non-negotiable boundaries

| Rule | Contract |
| --- | --- |
| Scheduler authority | Use `scripts/run_parallel_workflow.py`; do not replace it with an untracked or agent-private scheduler. |
| Task preservation | Add or update only the bounded TODO item belonging to the current concern. Never delete pending work or mark a broad requirement complete from one child result. |
| Parallel safety | Run only allowlisted read-only gates concurrently. Keep shared-file regeneration and dependent operations ordered or isolated. |
| Commit scope | One independently testable concern per commit. Review staged names, diff check, and statistics before committing. |
| Remote durability | Push every verified commit promptly to the configured remote and confirm `HEAD` matches its upstream. Never force-push or rewrite shared history. |
| Secret handling | Never place tokens in files, command arguments, URLs, logs, commits, or generated evidence. |
| Failure recovery | Preserve diagnostics, fix the same concern, rerun the failed gate, and retry the same reviewed commit/push. |

## Agent handoff record

Before ending a session, the agent must leave the repository in one of two explicit states. A clean synchronized state records the latest commit and successful verification command. A bounded in-progress state records only the relevant files, the failed or pending check, the exact next command, and the corresponding unchecked TODO item. Temporary logs, caches, extracted test material, credentials, and private notes are not substitutes for a committed handoff.

The authoritative machine-readable contract is [`agent_workflow.json`](agent_workflow.json). The current unchecked-task inventory is regenerated by `scripts/build_active_backlog_index.py`.
